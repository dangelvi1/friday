## Appointment calling follow-up (audit only)

The current server contains Twilio outbound calls, a Twilio/OpenAI realtime audio bridge, and a browser conference/listen/join page. The AI phone session currently has a hard-coded restaurant-test brief for two people tomorrow at 7 PM (alternatives 6–8 PM). That is not a general doctor/restaurant booking workflow, and no phone-to-calendar handoff was found. A successful prior live test is user-reported; no credentials/live provider operation was checked here.

Before adding a general voice command, the phone flow needs an owner-scoped call job: verified destination number, purpose, recipient, caller identity, allowed times, timezone, authorized information and selected Personal/Nationwide calendar. A displayed exact-call review should use the existing voice approval hub, with one-time submission/uncertain-outcome protection and cancellation/status. The callable legacy routes and media/callback paths need the relevant owner/provider validation; the fixed test script must not be reused for doctor calls. A call ending or voicemail does not prove an appointment was booked.

The proposed implementation should preserve the working transport and add modular phone appointment core/storage/service/routes/realtime modules, a dashboard call panel and one scoped voice tool. Structured confirmed call results should prepare the existing exact-calendar event review; ambiguous/unconfirmed times stay reviewable and must not become calendar events automatically. Personal and office calendars stay separate. Native writes/calls should be tested first with fixtures; a live test needs a specifically authorized destination/purpose, not an unsolicited doctor/restaurant call.

Pending clarification: use the existing FRIDAY/Twilio number or the owner's personal cellphone/caller ID? A cellphone number is not automatically a supported originating line merely because it is entered in the UI. No caller ID, account configuration or phone number is invented here.
